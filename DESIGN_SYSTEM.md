# Clinaxy Landing Design System

This document reflects the local Codex landing experiment in `D:\Clinaxy\ai-healthcare-codex-landing`.

## Direction

Premium, light-first, immersive-minimal healthcare SaaS for GPs, specialists, surgeons, and clinic teams.

The landing page should feel like the product is quietly running in front of the doctor:

- incoming work becomes a queue
- patient context arrives before the consult
- notes draft while the doctor stays present
- follow-up is prepared for review

## Palette

- Canvas: `#F6F4EE`
- Surface: `#FFFFFF`
- Ink: `#1C2A27`
- Muted: `#55625B`
- Line: `#E2DDD0`
- Teal signal: `#0E8A7D`
- Teal action: `#0A6256`
- Dark section: `#0B2926`
- Warm accent: `#C98A22`
- Urgency: `#C0392B`

## Type

- Primary: Hanken Grotesk
- Accent: Instrument Serif italic, used sparingly inside large headings
- Mono: Geist Mono for small status, queue, and pricing labels

## Motion

- Slow, calm, product-native motion
- Scroll-driven journey line
- Clickable modules that update the live UI visual
- No busy dashboards, stock photos, neon, generic medical imagery, or unearned trust badges

## Copy Rules

Always:

- Use plain clinical workflow language
- Speak to doctors and clinic teams, not tech buyers only
- Explain several modules working as one system
- Keep clinician review and approval clear
- Say the product assists workflow and documentation

Never:

- Claim patient data resides in Australia unless production deployment truly supports it
- Mention fake certifications or unverified compliance status
- Use HIPAA, SOC 2, Epic, Cerner, or US-centric trust language unless actually relevant
- Say "no credit card" because this funnel uses a 7-day trial with a card required
- Use fabricated testimonials, star ratings, or metrics
